# 灵山AI数字人导览系统 — 作品说明文档

---

## 一、需求分析

### 1.1 行业背景

传统景区导览面临三大痛点：
- **导览方式单一**：依赖纸质地图、固定解说牌、人工导游，无法提供个性化服务
- **信息获取碎片化**：游客想了解景点详情，需在不同平台间切换查找
- **高峰体验差**：节假日人流密集时，人工导游资源紧张，游客自助导览需求强烈

无锡灵山胜境是国家 5A 级景区，年接待游客超 300 万人次。景区面积达 30 万平方米，拥有 60+ 个景点和设施。本系统旨在通过 AI 技术，为游客提供"随身 AI 导游"体验。

### 1.2 核心需求

| 需求 | 描述 |
|------|------|
| 智能问答 | 游客可自由提问，AI 数字人基于知识库准确回答景区相关问题 |
| 语音交互 | 支持语音输入输出，解放双手，更适合户外游览场景 |
| 地图导航 | 精确标注景点和设施位置，支持路线规划，实时定位 |
| 拍照识景 | 对着景点拍照，AI 自动识别景区名称并提供介绍 |
| 个性化推荐 | 根据游客偏好、行为历史推荐合适的景点和路线 |
| 管理后台 | 景区运营方可查看数据统计、管理知识库和 FAQ |

### 1.3 用户角色

- **游客**：使用移动端 App 获取导览服务
- **景区管理员**：使用 Web 管理后台进行内容管理和数据分析

## 三、技术选型

### 3.1 技术栈总览

| 层次 | 技术 | 选型理由 |
|------|------|---------|
| 后端框架 | FastAPI (Python) | 原生异步支持，适配 LLM 流式响应；自动生成 API 文档 |
| 数据库 | SQLite + aiosqlite | 轻量零配置，适合景区内离线部署；异步驱动与 FastAPI 无缝配合 |
| 向量数据库 | ChromaDB | 开源、轻量、本地部署，适合中小规模知识库的语义检索 |
| LLM | DeepSeek (可切换 Qwen/OpenAI) | 高性价比中文大模型，支持流式输出 |
| 语音识别 | OpenAI Whisper (small) | 开源、中文识别准确率高、本地推理无延迟 |
| 语音合成 | Microsoft Edge-TTS | 免费、中文音色自然、支持多音色切换 |
| 图像识别 | EfficientNet-B3 (PyTorch) | 轻量 CNN，12 类灵山景点分类，本地推理零延迟 |
| 移动端 | React Native (Expo) | 跨平台一套代码，快速迭代；Expo 生态丰富 |
| 地图 | 百度地图 WebGL API | 国内景区定位精度高，POI 数据完整 |
| 管理后台 | Vue 3 + Ant Design Vue | 组件丰富、开箱即用、ECharts 集成自然 |
| 实时通信 | WebSocket | 支持 LLM 流式 token 推送 + TTS 音频有序交付 |

### 3.2 AI 能力矩阵

| AI 能力 | 实现方式 | 效果 |
|--------|---------|------|
| 智能问答 | DeepSeek LLM + RAG 知识库增强 | 基于景区知识库精准回答，非景区话题友好拒答 |
| 流式对话 | WebSocket + Server-Sent Events 模式 | Token 逐字流式返回，首字延迟 < 1s |
| 语音输入 | Whisper small 模型本地推理 | 中文识别准确率 > 95%，处理耗时 < 1s |
| 语音输出 | Edge-TTS 句级并行合成 + 有序交付 | 长文本边合成边播放，首句播放延迟 < 1.5s |
| 景物识别 | EfficientNet-B3 (12 类灵山景点) | Top-1 准确率 > 85%，推理耗时 < 200ms |
| 语义检索 | Sentence-Transformers + ChromaDB | 中英文跨语言检索，相关度排序 |
| 个性化推荐 | 协同过滤 + 内容推荐 + 行为信号融合 | 基于 14 万条游客行为数据，支持冷启动 |

## 四、实现方案

### 4.1 数字人实时对话流程

```
用户语音 → [Whisper ASR] → 用户文本
    → [ChromaDB RAG] 检索相关知识
    → [DeepSeek LLM] 流式生成回复
    → 逐句检测 → [Edge-TTS] 并行合成语音
    → 有序交付 → 手机播放（支持连续多句自动播放）
```

WebSocket 协议支持三种消息类型：
- `llm_token`：LLM 逐字推送（数字人口型同步）
- `tts_chunk`：音频片段有序交付（带序号确保播放顺序）
- `llm_done`：对话完成通知（触发推荐芯片展示）

### 4.2 景物识别流程

```
拍照/选图 → Base64 编码 → POST /api/recognition/identify
    → 图像预处理 (256x256, Normalize)
    → EfficientNet-B3 推理 → Softmax → Top-5 类别
    → 双条件验证（置信度 ≥50% + Top1/Top2 差距 ≥15pp）
    → 通过 → 展示 Top-5 结果 + "让 AI 讲解"按钮
    → 未通过 → 提示"未能识别出景区内容，请拍摄清晰照片"
```

### 4.3 RAG 知识库增强

- 知识条目：22 条结构化景点知识（含历史背景、建筑特色、文化内涵）
- 嵌入模型：paraphrase-multilingual-MiniLM-L12-v2（384 维）
- 检索策略：用户问题 → 向量相似度检索 → Top-1 相关知识 → 拼入 System Prompt

### 4.4 个性化推荐引擎

基于 14 万条真实游客行为数据（TouristBehavior 表），实现四层推荐策略：

1. **热门推荐**：按访问量 + 满意度排序
2. **画像推荐**：根据年龄、性别、预算、团体规模匹配
3. **协同过滤**："浏览过该景点的游客还喜欢……"
4. **个性化推荐**：对话关键词提取 + 浏览历史 + 收藏记录融合，不足时热门补齐

### 4.5 管理后台数据看板

单次 API 请求完成 10 个查询（2 个并行 gather 块），包含：
- 基础统计、游客年龄/性别分布、满意度分布、人均消费构成
- 热门景点 TOP10、景区类型热度、团体规模分布
- 30 天对话趋势、知识库来源分布、问答好评率

所有子查询独立 try/except，单个模块失败不影响整体。

## 五、创新点

### 5.1 句级流式 TTS 并行合成 + 有序交付

传统 TTS 需等全文合成完毕才能播放。本系统在 LLM 流式输出时实时检测句子边界，每检测到一个完整句子立即异步发送到 Edge-TTS 合成，通过序号机制确保音频按原文顺序播放。首句播放延迟从 8-15 秒降至 < 1.5 秒。

### 5.2 CNN 本地景物识别 + 双条件置信度过滤

使用 EfficientNet-B3 训练 12 类灵山景点识别模型，纯本地推理零网络延迟。针对 Softmax 强制 100% 分配导致非景区图片也得到高置信度的固有问题，设计了"置信度 ≥50% + Top-1/Top-2 差距 ≥15pp"的双条件过滤机制，有效拦截非景区图片的误识别。

### 5.3 四层混合推荐策略 + 冷启动兼容

融合热门、画像、协同过滤、个性化四层推荐策略，针对冷启动用户（无历史数据）直接返回热门景点，已登录用户则融合对话关键词兴趣信号和浏览收藏记录。

### 5.4 WebSocket 流式数字人对话

将 LLM 流式 token 推送、TTS 音频有序交付、数字人口型同步整合在单一 WebSocket 连接中，减少连接开销，提升实时性。

### 5.5 灵山禅意设计系统

围绕"禅意"主题打造统一设计语言：金色主调（佛光）、朱砂红点缀（祈福）、玉石绿（自然）、青金石蓝（天空）。移动端 8 个页面 + 管理后台 8 个页面全部遵循统一的色彩、圆角、阴影、间距体系。

## 八、项目亮点总结

1. **完整的 AI 多模态交互**：文本 + 语音 + 图像 + 数字人四通道融合
2. **端到端低延迟体验**：句级流式 TTS、本地模型推理、WebSocket 实时通信
3. **数据驱动的推荐系统**：基于 14 万条真实游客行为数据
4. **灵山禅意设计**：统一的东方美学设计语言
5. **三端完整覆盖**：移动端 + 管理后台 + 后端服务
6. **工程稳定性**：全局异常处理、分层降级、并行查询优化
